# 第72轮：两条路线的计算核心与误差范围

本轮保留两种输出：PNR 路线输出每端口 `uint32` 光子数量；直接点击路线输出二进制点击。核心分别为 C++ 与 CUDA C++，Python 组织实验、调用库和保存证据。没有用 Python 循环执行轨迹中的矩阵条件更新。

## PNR：带保护的 Newton 生存概率求根

第71轮的弱抽取分支模型保持不变，包括抽取强度 ε=0.001、分支预算2及跳变前条件触发值10⁶。谱分解后每个 Gaussian 分支的生存函数为

\[
S_j(s)=\exp\left[-\frac12\sum_i\left(\log(1+s\lambda_{ji})+\frac{s a_{ji}^2}{1+s\lambda_{ji}}\right)\right],\quad S(s)=\sum_j w_jS_j(s).
\]

求导可得

\[
S'_j(s)=-\frac12S_j(s)\sum_i\left(\frac{\lambda_{ji}}{1+s\lambda_{ji}}+\frac{a_{ji}^2}{(1+s\lambda_{ji})^2}\right).
\]

新核心以 `log(u)/S'(0)` 提供初值，保留 `[0,1]` 根区间。Newton 步越界或失效则二分；最多32次，未满足停止条件时退回64次二分。停止阈值为 `64*long_double_epsilon*(1+abs(u)+sum_abs_weighted_survival)`。这是有符号数值求和的算术停止条件，不是分布 TV 误差界。

400万条第71轮 PNR 记录被逐条完整重放，没有计数变化；另外六对相同种子的计时批次也独立核对。重放使用原始种子，不能计作新的独立统计复验。有限抽取会引入未观测衰减及多光子点击当作单次跳变的偏差；分支合并丢失高阶信息。新求根器没有消除这些偏差，也没有证明在所有输入、所有种子上与旧浮点实现完全相同。接口报告迭代数、回退次数及最大生存残差，保留显式失败，不设光子数截断。

## 直接点击：FP64 CUDA 有符号 Gaussian 分支

采用第71轮的 Gaussian 差态表示和预算超限矩合并。一个128线程 CUDA block 处理一条轨迹，各线程协作执行协方差乘向量与二阶更新；分支矩阵按列存储，求和使用补偿，禁用 FMA 收缩和 fast math。预算1使用既有解析矩更新。GPU 与 CPU 的浮点路径不同，因此分别核对完整小系统诱导律、逐步条件概率和同随机输入的点击记录。

CPU C++ 生成与第71轮一致的每条轨迹位移噪声和探测随机数；GPU 执行逐端口条件更新。接口的条件概率对应已实现位移和路径，不是积分噪声后的前缀概率。计算时间包括随机数、分配、传输、内核及输出拷贝；每次重新准备模型，未跨调用缓存 GPU 工作区。

当前实现明确限制：输入数≤128、输出数≤65536、预算≤128、批量≤1048576；工作区估算超过空闲显存75%时拒绝。真正验证的最大输入数为50、输出数144，不能用接口上限冒充已验证规模。零概率下溢、非有限矩阵、非法概率、丢失权重及失败归一化均显式报错，不裁剪概率、不丢弃失败轨迹。已完成的成功面板没有这些失败，但这不构成其他输入的稳定性证明。

充分分支数下的 Gaussian 差态阈值算法已有先例：[Quesada 等，2018](https://arxiv.org/abs/1807.01639)。本轮贡献是受预算限制的实现、CUDA 调度和可复核证据，不将该恒等式作为新发明。PNR 重置相关先例见 [Lim，2026](https://arxiv.org/abs/2610.06526)；弱抽取分支扩展及其局限见[第71轮方法](iteration71_methods.md)。

## Frugal CUDA 基线的可复现范围

固定作者仓库提交 `fa8b796f2afebd4845a2e335e457735952617ef8`，补全15个官方 GPU 文件并核对 Git blob 和 SHA-256。保留 MIT 许可。GPU 采样及累积量内核未修改；单精度为官方默认设置，另测双精度。

Windows CUDA/MSVC 构建遇到四次失败，v1～v4 的完整输出均保留。v5 使用分开的主机与 CUDA 翻译单元；Eigen 仅用于 CPU，按[官方文档](https://eigen.tuxfamily.org/dox/TopicCUDA.html)启用 `EIGEN_NO_CUDA` 并关闭其向量化。主机布局递归的 bitstring 参数按值传递，并将两个 OpenMP 递归任务改成串行递归，绕过 MSVC 内部错误；累积量准备中的并行相关函数仍使用16线程。改动只发生在临时构建副本，官方原始文件不改，完整差异见[构建证据](../results/iteration72_frugal_gpu_build_v5/host_layout_compatibility.diff)。这是带主机兼容改动的官方 GPU 核心，不能称整个构建完全未修改。

作者代码使用 `#if FGBS_REAL_PRECISION < 2` 选择 CURAND 函数，但该配置由 C++ constexpr 定义，所以这份固定版本在两个精度设置中均选用 float 均匀随机数函数；实际累积量和缓存类型分别为 FP32/FP64。原样保留，不在基线中暗改随机数实现。Frugal 自身的概率裁剪也原样保留。

先测真空及四/八模各10万条记录，分别对比完整目标或已枚举的 Frugal 诱导律，再做144模三个交错重复。大面板三种分支预算与四种 Frugal 配置均使用512条记录。官方 CUDA 每128条轨迹构成一个 block，这个批量只有4个采样 block；其时间不能代表大批量峰值吞吐率。主机兼容布局耗时与 GPU 采样耗时分别公开，避免把兼容成本藏入总时间。

大系统两种近似律没有完整144位联合分布 TV 上界，因此只能比较这一面板的实际成本。四模使用完整分支与全阶 Frugal 配置；Frugal 的参照律取自此前 CPU 枚举，GPU 本身以10万样本作经验核对，不能把 CPU 枚举误差直接当作 GPU 完整 TV 的证明。八模保留参照诱导律误差并同时报时间，避免把更低预算的速度当作同质量胜出。浮点条件概率形成的诱导律也未纳入有限 PRNG 网格的全局误差证明。
