# 实际森林核的显式标量边界

## 两个不同问题

Windows本机的Python `np.longdouble` / `ctypes.c_longdouble` 为8字节、53位尾数，而GCC native long double为16字节、64位尾数。旧ABI直接交换long double，布局检查拒绝是正确行为，不能删除。另一个独立问题是Python宿主x87控制字0x027f仅执行53位精度，即使C++类型报告64位；仅修正布局仍会执行错误精度的运算。

第28轮已用隔离原型确认这一点。本轮通过 `WireForestKernel` / `WireForestSampler` 接入真实 `bf_probability` 及原始事件批。`batched_forest_kernel.cpp/.h`、旧Python适配器和第28轮编码原型均保持原样，新入口显式选用。它改变传输与调用环境，不改变条件森林代理规则。

## 编码和算术范围

固定24字节：1字节标签、1字节符号、2字节保留零、4字节小端有符号指数、16字节小端无符号尾数。正非零尾数必须为奇数，值为(−1)^sign M·2^e；零唯一编码为全零。解码拒绝非规范数据、不精确可表示的guard及越界值。Python用整数与Fraction恢复原数，不经过Python float。

协方差输入本来就是binary64，沿用原始double数组；查询索引、状态和计数为整数。事件值、绝对误差指标、两个log score、两个log indicator及两个最大指标均走显式dyadic编码。最终用于抽样的Bernoulli概率仍是核内按旧端点规则验证过的binary64值。

原核的quad事件路径仍先转为native long double并加入转换误差指标，评分仍使用native long double；新边界无损保留这些值，**没有把既有评分器升级为全程113位，也没有消除固有数值误差**。`query/probability` 的精确Fraction字段和原始wire字节可审计；继承的 `conditional_details` 部分展示字段继续转为普通float，只供旧接口展示，不参与原生事件/评分运算，不能把它们当成全精度导出。

## 调用环境和错误语义

所有新计算入口在进入原核前建立x87 64位精度/最近舍入，SSE最近舍入并关闭FTZ/DAZ；退出包括错误路径恢复原控制字段。这里明确保证的是测试覆盖的控制字段，不宣称保留全部处理器异常状态。句柄仍为单线程使用。

AUTO策略不变：最多一次long double批次，只有数值错误才进行一次独立quad批次；保留集合、森林边、阈值和随机数都不重新选择。参数/资源/程序错误不触发精炼；精度耗尽仍是失败符号，不将其变为解析零，不重抽补齐。原核误差指标仍是启发式前向跟踪，不是严格区间。

## 验证为什么不止编码往返

- 独立可执行程序直接调用未改动的科学核，用native `%La` 文本输出；Python通过整数解析这些十六进制数，与新接口wire字节逐位核对。
- 新接口又在三个宿主设置下运行，包括故意设为53位、向上舍入及FTZ/DAZ开启。结果应等于标准环境下的原生计算，返回后控制字段应等于进入前。
- 19项模块测试含10项继承的数值语义测试：真正LD→quad精炼、预算耗尽、端点拒绝、含失败符号概率律、无额外随机数、历史/缓存一致性等。
- 完整小系统法则与独立Gaussian事件表对照，并从保存的条件概率重新构造完整法则、独立重放2,048条随机数流。144模式只检查运行和成本，不借32条样本推断分布质量。

## 显式使用

先运行 `experiments/build_wire_forest.py --compiler <GCC路径> --output <不存在的新目录>`，再向 `WireForestKernel` 或 `WireForestSampler` 的 `library` 参数传入生成的 `libwire_forest.dll`。库的SHA、源文件绑定及运行库SHA在加载时检查；不隐式编译。构建路径变化或平台变化应重建，而不是绕过校验。当前只验证Windows x86-64/GCC，不把协议的明确字节定义当成所有架构已通过验证。

新路径成功不消除其它原生程序的构建依赖，也不使有限MPS采样器、Gaussian目标或森林代理彼此等价。第30轮有限MPS完整混合输出与本轮Gaussian条件森林是不同的近似路线，质量应分别评价。
