# 第73轮：同时推进光子数量与直接点击

## 光子数量路线

1. 由有限弱抽取近似转向解析光子跳变的 Gaussian×低阶多项式表示，直接处理导数项，减少 ε 偏差和相反大权重相消。以四模完整 PNR 分布、均值和极端尾部作为第一道检验。
2. 固定输入、固定误差目标扫描 ε 与分支预算，记录全部失败和耗时；Newton 的计算改进不被重复算作分布改进。
3. 完成144输出、50输入的 C++ 计数吞吐对照，再考虑将重复谱计算与跳变权重扫描迁移到 GPU；不能用四模3倍加速推断大系统加速。

## 直接点击路线

1. 测量512、4096及更大批量，在显存允许范围内分别比较当前 CPU 与 CUDA Frugal。优先修复通用 CPU 之外的本机指令集构建，避免把一个较慢构建当成工具极限。
2. GPU 保持动态分支数而减少最大预算工作区；测试按相消强度和路径历史自适应预算。条件数只用于数值风险判断，另行建立误差界。
   同时将位移与探测随机数生成迁移到 GPU：第72轮小系统总耗时显著高于内核耗时，CPU 逐轨迹初始化随机数引擎是应单独测量的成本。新随机数路线须另存原始结果，不覆盖共同随机输入回放证据。
3. 从已有四/八模完整目标扩展可枚举的固定输入集；大系统同时对照低阶相关、计数分布和可计算事件。通过这些检查也不等于完整联合 TV 认证。

## 共同交付条件

每轮冻结首次执行源码和原始结果，失败保留为独立版本；计算核心采用 C++/CUDA，Python 作为调用与实验脚本。公开接口回放、独立证据核验和完整测试通过后发布 GitHub。持续报告 Frugal、九章2.0/3.0的明确任务差异、原始时间差距和输入规模差距；不宣称已覆盖任意维度或已实现同质量量子优势。
