## 1. 必须保持的状态与概率不变量

### 1.1 Gaussian 状态只施加零观测

当前协方差 W 必须描述原始 Gaussian 态在所有已观测零位置 Z 上投影真空后的归一化 Gaussian 态。它没有施加旧点击的非 Gaussian 条件。

- 观测 0 时，对该模式作 Gaussian 真空条件化，并从 W 的物理模式列表移除。
- 观测 1 时，把该模式加入完整点击历史，**仍在 W 中保留它**。
- 所有旧点击都可以再次进入候选集合，不能只在 W 中保留最近 k 个或当前选中的 k 个。

按 hbar=2，测量模式的 2×2 协方差为 A、与剩余变量的交叉块为 B 时，零更新是

\[
 W_{\rm remain}=W_{RR}-B(A+I_2)^{-1}B^T.
\]

实现应解线性系统而非无条件采用容易溢出的行列式逆公式。对称化可以消除舍入反对称部分，但不能以任意对角噪声掩盖不合法状态。

### 1.2 坐标、事件与数值约定

输入是零均值、真空 I、xxpp 坐标。删除零模式后，p 坐标偏移是**当前活动模式数**，不是原始 m。物理模式编号、活动矩阵位置、测量顺序位置须区分。

真空部分事件为

\[
 v(S)=\det[(W_S+I)/2]^{-1/2}.
\]

对选中的旧点击 C 和下一模式 j：

\[
 d=\sum_{T\subseteq C}(-1)^{|T|}v(T),\quad
 a=\sum_{T\subseteq C}(-1)^{|T|}v(T\cup\{j\}),\quad
 p_1=1-a/d.
\]

空集真空概率是 1。包含排除使用 long double 求和，但行列式仍是 double；增加累加精度不等于严格数值认证。保留分母、相消指标、非有限值和超出概率区间的检查；不能把未解析分母随意替换为 1/2，也不能删除极小支路来制造通过。

### 1.3 选择与采样语义

点击影响选择从空集开始，按

\[
 |P(X_j=1\mid Z0,C1,X_a=1)-P(X_j=1\mid Z0,C1)|
\]

贪心选择下一候选 a。选入 a 后更新基准概率，再进行下一轮。相同分数按较小**物理模式 ID**决胜。未经说明的 epsilon 平局区间会改变算法，不应加入等价移植。

随机分支与 Python 相同：每个模式消耗一个均匀数，判断严格使用 `u < p_one`；即使 p_one 为 0 或 1，也不跳过均匀数。注入随机数按测量位置排列，返回样本与完整分布位掩码按物理模式排列。

完整 Q 的强制分支与实际采样应调用同一条件概率和状态更新路径。概率为零的强制支路可立即停止，不能继续进入不可能条件事件。

### 1.4 大模式不能偷偷构造指数级数据

采样路径最多保存协方差、有限缓存、点击历史和 O(样本数×模式数) 输出。只有在明确要求完整分布且通过小规模上限检查之后，才能分配 2^m 概率数组。

尤其注意 C++ 中 `1ULL << 64` 的未定义行为：64 模式采样时，不能为了未使用的直方图、状态键或辅助统计先执行这种位移。编译期不同模式的官方适配器应以 `if constexpr` 隔离指数级/超宽位移代码。

## 2. 数值等价与边界检查

原 Python 的 `slogdet`、缓存父状态更新顺序与 Eigen Cholesky 的舍入路径不同。单个概率或互信息的 ulp 级差异在接近并列的贪心分数上可能改变所选集合。因此应同时查看：完整小规模 Q、给定均匀数的样本、逐步 p_one、所选物理 ID 和相消指标。

必要夹具包括：非相同独立热态（检查 hbar 与坐标排序）；独立双模压缩对的分块及交错顺序（检查旧点击保留和零条件化）；含 xp 相关的非均匀随机 Gaussian 输入；置换测量顺序；真空与确定性分支；禁止大规模枚举的资源边界。

已向实现与测试负责人说明这些要求。目标是数学与概率语义保持一致，不能用跨编译器逐位浮点相等替代合理的数值审计，也不能把明显的完整 Q 差异都归咎于舍入。

## 3. 性能比较与 SIMD/汇编判断标准

新的本项目 C++ 和官方 FrugalGBS 使用相同的优化级别、体系结构目标、精度、线程数、输入、样本数量，以及相同的初始化/采样计时边界。原先非 native 指令集的第二轮 Frugal 结果保持冻结，不能直接拿它与新 native 程序混算而不说明差别。

`-ffp-contract=off` 限制编译器自动融合，不代表 Eigen 内部不会显式调用 FMA 指令。不要使用 `-ffast-math`/`-Ofast` 使概率检查的非有限值假设失效。

先量出选择、行列式、零条件化、缓存/分配和随机数等成本。选择时间可能包含其内部的行列式时间，汇总时必须区分包含关系，不能把重叠计时加成“总耗时”。

未经缓存的贪心选择，在 c>k 个旧点击时需要

\[
 1+\sum_{s=0}^{k-1}(c-s)(2^{s+2}-1)
\]

次小行列式计算，若最后概率另算，再加 2^(k+1)−1。c=10、k=4 时为 431+31=462 次。这个计数不是实测瓶颈；它提示若剖析证实行列式/分配占主导，复用子集真空概率与最后一次贪心基准可能比手写汇编更有价值。

只有在实际剖析显示一个稳定、占比显著且编译器未有效向量化的内核后，才有依据尝试显式 SIMD 或汇编。优化后仍需重复概率与支持检查，并以端到端成本验证收益。

## 4. 实现核查与实际结果

### 4.1 第一版源代码审阅

已逐段阅读 `experiments/click_sampler.cpp`、`experiments/build_click_sampler.py`、`src/gbslab/cpp_click.py` 和原生 Frugal 采样入口。第一版中未发现状态、坐标、概率符号或测量顺序错误：

- `State::project_zero` 的两个 Cholesky 变换向量实现正确的 rank-two Schur 更新，只移除零模式；点击分支不改变 Gaussian 矩阵。
- `fixed_vacuum` 先构造 (W+I)/2，以 Cholesky 对角的对数和得到逆平方根行列式；事件核用 long double 作带符号累加。
- 贪心中间事件保留选择顺序；最终采样事件将已选物理 ID 排序，与 Python 的两条相应路径一致。
- 强制完整分布的 DFS 与真实抽样调用同一个条件核，输出掩码使用物理 ID；只有零分支复制并更新 Gaussian 状态。
- 大模式不构造完整掩码直方图，采样可跨越 64 位边界；所有完整位移操作都在 m≤14 分支内。原始样本、注入随机数和跟踪数组分别有显式内存/步数上限。
- 剖析计时器只有 `--profile` 时读取时钟；输出明确说明选择计时与选择内部事件计时的包含关系。

集成验证器的“前 k+1 个测量结果等于物理目标边缘”断言正确：在这段前缀中还没有可能遗漏旧点击。它使用任意测量顺序对应的物理模式边缘，不是直接取低 k+1 位。

严格支持/极弱事件压力例只允许把非零退出且明确报告 `error_type=numerical_probability` 的结果记为数值保护；非法 JSON、非法概率及其他失败不会伪装成允许的保护。压力例必须和普通数值等价例分开报告。审阅建议补充的实际诊断字段名称检查、非空验证归档目录保护和中断日志均由测试负责人接纳。

### 4.3 计时边界审计

第一版在采样计时前创建随机数引擎和输出缓冲，却在采样循环中计直方图；官方 Frugal 的公共调用把随机数/输出分配计入抽样、把直方图留到之后。第一版关闭 raw JSON 时还只维护流式统计，而官方 API 始终保存一批样本。

该初版阶段尚无“C++ 已获胜”或“需要手写汇编”的审计结论；后续冻结验证与正式对赛分别记录在下文。

### 4.4 缓存、样本实体化与固定验证

对齐计时后冻结的 native 二进制 SHA256 为：

```text
021e7d14ee43f9659809a0c7fe2add871dc9f0a551d4cbf389fcb8321adf4bd5
```

新缓存仅在需要贪心选择的单个条件概率计算中有效。键按原计算顺序保存最多 9 个物理模式 ID，并单独编码长度：前 8 个 ID 占低 64 位的各字节，第 9 个 ID 与长度占高字的不同字节。模式 ID 在 0…255 范围，故不能因末尾 ID 为 0 或模式数不同而碰撞；保留顺序避免把不同 Cholesky 排列的舍入值混用。

每次条件计算重置 generation；generation 回绕时清空旧标记。表占用不超过容量一半，开放寻址能找到空槽。容量最多 131072 个表项，实际存储概率不超过 65536 个。DFS 递归前已经得到父节点概率，父节点不保存随后被重置的缓存引用。此审阅未发现跨状态概率污染或索引错误。

所有运行均分配并保存 packed uint64 样本，关闭 raw JSON 仅减少序列化。索引采用 `mode/64` 和 `mode%64`，位移不超过 63；最后一个不满字的高位保持零。随机数引擎、样本缓冲及抽样纳入 sampling，直方图等聚合移到独立 aggregation 时间。

`results/cpp_validation/native_cached.json` 记录新二进制重新执行固定 35 例验证：29 个普通例全部通过，6 个压力例触发明确数值保护。普通例完整 Q 与 Python 的最大 TV 为约 3.61e-14，注入均匀数样本均一致。`native_version_comparison.json` 直接比较旧、新二进制归档：26 个可完成的完整 Q 和 29 批样本逐位相同；压力例不冒充完成的分布比较。

`native_cached_support.json` 使用原压力例归档中的相同均匀数单独回放抽样：4 个严格双模对批次抽样完成且没有观测到禁止模式；2 个极弱热态例在抽样中仍触发保护。这是有限历史检查，不是任意输入支持正确性的认证。同二进制关闭/启用缓存的 bright12 和反序 heterogeneous10 检查也得到逐位相同的完整 Q 与样本。

### 4.5 正式对赛发现：稀疏局域输入的 pairwise 选择不稳定

固定验证没有包含局域浅层干涉输入。正式 cold 对赛补足这一覆盖后，27 个 `click_influence` 完整 Q 均通过旧 Python 同规则检查，但 `cpp_pairwise` 在 13 个 local2/local4 输入上超出预定 2e-8 的移植等价门槛。失败原件在 `results/cpp_cold/failures.json`，计算出的 Q 仍保存在各 `laws_CASE.npz`；不能放宽门槛把失败重新解释为通过。

独立逐例读取归档得到这 13 例的 TV(Q_cpp,Q_python) 范围为 3.2082992541260625e-8 到 0.004377654238046784。最大例为 `a71ab6f032848177`（10 模式 local2）：

- 下一模式 j=9，过去 9 位模式掩码为 466，故旧点击 C=(1,4,6,7,8)，旧零 Z=(0,2,3,5)。
- Python 保留集合为 (8,7,6,1)，条件点击概率为 0.4193112741239704。
- 冻结 C++ 保留集合为 (1,4,7,8)，条件点击概率为 0.5630043770765315。
- 在**相同 Python 概率核**中指定 C++ 的保留集合，得到 0.5630043770765272。约 0.144 的差异来自所选约束，不是条件事件公式误差。
- 完整旧点击条件的概率为 0.4198235847540277。

目标模式 9 与模式 1、4、6 的三个 2×2 协方差交叉块均为**严格的浮点零矩阵**。零均值 Gaussian 的二模约化态因此为积态，其无条件阈值互信息数学上恰为 0。然而 Python 的浮点计算给 MI(9,6)=6.990199121852346e-18，给 MI(9,1)=MI(9,4)=0。原代码按计算出的实数严格排序，微小舍入残差便把数学平局变成不同排名。80 位 Decimal 的 2×2/4×4 行列式直接复算也确认这些值在高精度算术误差内为零；零交叉块本身提供精确的结构性理由。

“与目标无条件成对独立”不等于“给定其他点击和零结果后不相关”。在上例，保留模式 7、8 等约束后，模式 6 的点击会显著改变目标条件概率。因此不能声称零 MI 平局仅影响无关模式、不会改变 Q。这也是局域输入验证不可由独立热态或稠密 Haar 输入替代的原因。

建议的最小、可解释修复是明确规定：严格零协方差交叉块直接给互信息 0，再按物理 ID 打破平局。这利用 Gaussian 积态性质，不引入任意 epsilon 分数区间。它仍需检查全部失败例是否还涉及近零但非零的分数；任何新实现/参考都应另存版本并重新验证，保留原失败和原 Python 结果。本节先记录已证实的原因，不预先声称所有 13 例已经修复。

独立筛查也确实发现了不能并入“结构零”的弱相关：`22c3418bd5ab4f76` 的模式 (8,2) 交叉块最大元素为 5.3172703694855904e-5，80 位 Decimal 复算得到 P00−P0P0=5.32380139760041e-10、MI=3.34509738101169e-17，而原 Python 得到 0。其他 local4 例也有 1e-16…1e-15 量级的真实互信息。结构零规则必须只作用于严格零块；不能靠增大分数阈值掩盖这类值。

若后续需要稳定计算弱互信息，可利用归一化二元分布的恒等式

\[
 I=\sum_i r_i\big[(1+x_i)\log(1+x_i)-x_i\big],\qquad
 r_i=p_{X,i_X}p_{Y,i_Y},\quad x_i=(p_i-r_i)/r_i.
\]

小 x 的方括号使用 x²/2−x³/6+x⁴/12−⋯，避免四个一阶项相消后留下比真实 MI 还大的舍入噪声。这是潜在数值修复，不是已执行的结果。原第二轮 pairwise 表仍是当时实现的真实输出，但其稀疏输入排名不能表述为不依赖数值实现的数学结果；新的标准化平局控制应另行报告。

### 4.6 剖析与匹配基线的已完成检查

初版 M=12、k=4、1024 样本剖析中，点击影响方法的事件计算约占采样时间 90.4%，其中选集内部占约 58.4%。这给先复用真空子集概率提供了直接依据。

冻结缓存版本的同一二进制、同一输入、同一随机种子 cache-off/cache-on 剖析中，小行列式次数从 388680 减到 188498（约 51.5%）；采样时间从 0.071024964 秒减到 0.049991965 秒（约 29.6%）。两个版本的完整 Q 与注入均匀数样本另有等价检查。该单例启用剖析计时器，不能替代重复的正式吞吐对赛；目前没有证据证明手写汇编比减少重复计算更值得先做。

重新构建的官方 Frugal native 二进制为 `3131fc80e293eb748032a7e8d7c27b7e4f8a53ecfe78be306e7ffa632170e1a0`。`results/cpp_frugal_validation/validation.json` 记录 10 个新验证例，包含发生阈值饱和的 N=8/K=5 例，以及 M=16、32、64 的真空抽样例。小规模强制支路 Q 与原 SSE 跟踪 Q 的最大 TV 约 2.49e-15；这是新程序的实际验证，并非直接沿用旧验证。大模式例只检查真空和输出结构，不能据此宣称相关大系统分布精确。

正式 runner 比较相同 GCC 可执行文件、`-O3 -march=native -ffp-contract=off`、单线程、相同协方差及样本数，旋转方法运行顺序。核心采样发生在完整 Q 枚举之前，未被枚举结果热身。cold 第 0 次重复的 wrapper wall 时间仍包含随后进行的枚举，因此报告抽样端到端延迟时应单独采用未枚举的重复；setup+sampling 核心时间不受此问题影响。

### 4.7 稳定互信息的独立数值验证与源代码复核

结构零以外的弱相关也需要保留。设二模真空矩阵使用未除以 2 的分块 A=V_aa+I、B=V_bb+I、C=V_ab，令 A=L_A L_A^T、B=L_B L_B^T，定义

\[
 T=L_A^{-1}C L_B^{-T},\quad
 s=\|T\|_F^2-\det(T)^2.
\]

二阶块的行列式恒等式给出 det(I−TT^T)=1−s，因而可直接算

\[
 \delta=P(00)-P_a(0)P_b(0)
 =q_aq_b\operatorname{expm1}\!\left[-\tfrac12\operatorname{log1p}(-s)\right].
\]

这里需要 0≤s<1。用 δ 形成四个联合概率的有符号偏差 (+δ,−δ,−δ,+δ)，再用前述 KL 余项，避免两个层次的相消。小 |x|≤1e-3 时采用 x² 到 x⁸ 的七项多项式，截断余项在边界约不超过 1.4e-29；这不是把小分数视为零的规则。

独立验证已归档在 `results/cpp_numerics_audit/`，包含 `verify_stable_mi.py`、6 个冻结协方差的 `fixtures.npz`、输入清单和 `results.json`。重跑方式：

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python results/cpp_numerics_audit/verify_stable_mi.py --output /tmp/gbs_mi_audit_replay.json
```

脚本不导入生产互信息函数。参考使用 80 位 Decimal，对存档 float64 元素的精确十进制表示直接作 2×2/4×4 行列式排列求和，再计算联合分布与 MI。被测恒等式故意用 NumPy float64 Cholesky/求解加 long double 标量，与生产版的显式 long double 标量分解不同。

| 输入与二模对 | 80 位参考 MI | 独立稳定公式相对误差 |
|---|---:|---:|
| local4 `22c3418bd5ab4f76`，(8,1) | 2.5043659391485971e-16 | 7.72e-16 |
| 同输入，(8,2) | 3.3450973810116876e-17 | 2.13e-15 |
| local4 `8670a2147006a38a`，(8,2) | 3.5329172131703429e-17 | 4.00e-16 |
| local2 `a71ab6f032848177`，(9,7) | .0098285248551655658 | 5.10e-16 |
| 物理弱相关经典 Gaussian，C=1e-4 I | 3.1843651689401726e-19 | 7.16e-16 |

第 6 例为点击率 p=1/2 的双模压缩对，其理想 MI=ln2。存储的 float64 协方差因平方根舍入有极小边界不一致；该例明确使用理想态的解析参考，并记录允许范围内的负联合概率修正，未把有负质量的高精度浮点矩阵分布冒充物理参考。修正后的稳定计算与 ln2 在本机 long double 显示精度一致。

C++ 新帮助函数的静态检查已确认：右侧三角求解的坐标正确；s 使用平方范数减平方行列式；KL 多项式符号正确；x=−1 单独取 h=1；负概率、规范化和修正量仍受原阈值限制；有修正时重算边缘；无修正时保留共同 δ。审阅中要求 Python 对齐 C++ 的单模真空范围检查/微小越界修正，以及修正后用联合概率显式求两项边缘的顺序。此修复只作用于 retained-click 的 Gaussian pairwise 选集分数，不改变 `click_influence` 或条件事件核；普通无协方差 oracle 仍保持兼容。

另外逐段与旧版源码比较，零投影、固定维数真空核、子集真空/缓存函数、条件事件核、选择循环、最终条件函数、状态推进、完整 Q 的 DFS 以及计时内整个采样循环均逐字节相同。旧源码完整保存在 `results/cpp_cold/source_snapshot/click_sampler.cpp`，SHA256 为 `8a7d6205e1c2b7dbcb77a6e939a3ee0945aa30ceaf460fa1b1194bbcb7c01d1b`。这里的“选择循环不变”指使用分数的逻辑不变；pairwise 的分数预计算已被明确替换。源码隔离检查支持主方法未被这项修复改写，但仍需新二进制的概率验证。

## 5. 正式结果的独立复算

最终三个阶段分别是 `results/cpp_cold_v2/`、`results/cpp_steady/`、`results/cpp_large/`，含 **243、81、42 行，共 366 行**正式计时，失败数均为 0。已核对三个阶段均绑定上述最终 C++ 与 Frugal 二进制，并重新计算汇总里的逐输入中位数比值。另从原始数组复算短批阶段 **81 个完整分布**的规范化和物理目标 TV，均与 CSV 一致。主要候选与原 Python 同规则 Q 的最大 TV 差为 **9.462116672972477e-14**。

### 5.1 短批与持续抽样必须分开

以下“核心速度比”直接先在每个输入上算 Frugal 时间 / 候选时间，再对输入求中位数；“抽样慢倍数”方向相反，是候选 / Frugal。偶数个输入的两种比值中位数不应不加说明地互取倒数。

| 工作负载 | 输入数 | 主要候选更快的数量 | 逐输入比值中位数 |
|---|---:|---:|---:|
| 10 模式，设置 + 128 样本 | 24 | 23 | 核心速度比 2.92544 |
| 12 模式，设置 + 128 样本 | 3 | 3 | 核心速度比 1.90144 |
| 10 模式，8192 样本，仅抽样 | 6 | 0 | 抽样慢倍数 6.97084 |
| 12 模式，8192 样本，仅抽样 | 3 | 0 | 抽样慢倍数 8.78844 |

短批阶段主要候选在全部 **27/27** 输入上的完整 TV 较 Frugal K=5 小，但核心时间只在 **26/27** 较快。例外是 `b7e6861062dd571a`，Frugal/候选核心时间比为 **0.9615225874**，即候选在本次重复中位数上约慢 4%。不能把最初旧二进制试验的“27/27 更快”沿用到最终结果。

持续抽样的 9 个输入，候选的抽样吞吐均较慢，质量值来自相同输入、参数、二进制的短批完整 Q。该方法在短批次的成本优势不能表述为更高的普遍采样吞吐，也不能据 3 次重复宣称总体统计显著性。

### 5.2 大模式只有成本证据

16、32、64 模式各 2 个输入，每次 512 样本，候选设置加抽样的逐输入核心速度比中位数分别为 **5.13761、29.33723、152.68819**。例如 64 模式第一输入为候选 **0.522845911 秒**、Frugal **81.604833615 秒**；第二输入为 **0.528200658 秒**与 **78.859410271 秒**。64 模式每个输入只有一次重复。

32、64 模式在仅抽样时间上也测得候选更快，但这些实验未获得完整 TV 或匹配误差保证。以上只比较固定 k=4 与 K=5 在这些输入上的实际成本，不能推出在相同物理准确率下领先，更不能推翻量子优势。

## 6. 最终审阅结论

已复核填入正式结果的 `RESEARCH_REPORT_CPP.md`、`README.md`、机器可读摘要和科学绘图。主要计数、各比值方向、设置摊销解释和大系统质量限制与归档相符；修复后的控制有变差例、旧失败和旧数值实现均被保留。分析中新增的逆向速度比采用逐输入倒数后取中位数，未把偶数样本的两个中位数误当成严格倒数。线性摊销交叉点约 231–290 个样本明确标为模型估算，不是实测阈值。

在本次审阅范围内，没有发现需要阻止本轮结果归档的未处理问题。此结论不升级数值验证为严格支持或区间证书，不把固定参数/单线程成本比较升级为匹配误差或量子优势结论。后续若改变概率核、选择策略、算术精度、编译二进制或输入分布，仍应重新建立对应验证和质量证据。
