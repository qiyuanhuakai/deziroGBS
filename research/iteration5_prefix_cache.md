# 第五轮：有界完整前缀缓存，保持原采样律

基线为 `37518d5`。本节记录实现、等价性依据和已执行的正确性门槛；正式跨规模性能结果由独立运行器记录，不用本节的测试运行时间作速度结论。

## 1. 改动与接口

新增显式可选参数：

```python
run_cpp_click(
    covariance,
    selection="click_influence",
    max_clicks=4,
    vacuum_kernel="product",
    prefix_cache_entries=65536,
    record_log_probabilities=True,
    executable=".cache/click-prefix-native/click_sampler",
    samples=1024,
)
```

C++ 对应 `--prefix-cache-entries N`。默认 `N=0`，不分配前缀缓存；Python 默认调用不传新开关，仍可使用已归档的旧可执行程序。启用缓存时必须返回相应元数据，包装器不会把缺失或矛盾的缓存记录解释为成功。

缓存是单批次内的一棵二叉前缀树。每个节点表示**完整的已测历史**，包括此前每个零和点击。固定输入协方差、模式顺序、选择器、k、真空核等参数都属于本次进程，缓存不会跨模型、顺序或批次共用。

每个节点存储已经成功算出的 `Conditional`（实际 double 点击概率、相消指标、条件事件分母）、原先选中的至多8个物理点击模式，以及两个子节点索引。没有存目标 P 的全分布，也没有用枚举结果预热。

## 2. 为什么不改变 Q

设固定参数下，原程序在历史前缀 h 上返回的实际条件概率为 f(h)。其成功二值输出的概率为

\[
Q(x)=\prod_{j=0}^{m-1} f(x_{<j})^{x_j}
\bigl[1-f(x_{<j})\bigr]^{1-x_j}.
\]

这里的位序是固定测量顺序，最终输出再按物理模式存储。f 已经包含原有有限点击记忆近似及浮点保护；它不是理想目标 P 的精确条件概率。

树中的路径就是 h 本身，无哈希冲突或历史截断。首次到达 h 时仍执行原算法，把成功结果存入节点；再次到达时使用同一个已计算 double 值和保留集合。无论此前哪些样本填充了树，本步 f(h) 不变。每一模式仍消费恰好一个原先位置的 uniform，比较方式仍为 `uniform < p_one`。

因此，在相同确定性浮点计算环境和足够运行资源下，这只是同一条件链的记忆化求值。缓存的自适应填充不改变后续样本的分布；对于独立理想均匀随机数，样本仍来自相同 Q。它不把有限PRNG状态枚举当成理想连续随机数概率。

`log Q` 的代码保持原样：每次按实际采样分支，用 long double 累加 `log(p_one)` 或 `log1p(-p_one)`，最终以 double 输出。缓存提供的就是当时用于比较uniform的条件概率，不重新拟合密度。

## 3. 惰性状态重建与失败语义

原 Gaussian 状态只条件于此前全部零；全部点击在独立历史列表中保留。完整前缀确定零的位置，也确定原程序执行零投影的先后顺序。

新样本先从缓存根开始。只要命中，就暂不复制协方差或执行零投影；记录经过的零及其原测量位置。遇到首个缺失节点，才从相同初始协方差创建 `State`，按原顺序调用**未改动的** `State::project_zero`，重放所有此前零，再调用原条件核。后续未命中的尾部继续执行原程序。

必须保留的细节如下：

- 命中后仍把每个点击加入完整点击历史，不能只留下缓存节点里的k个选中点击。
- 重放使用原矩阵维度、模式位置映射和算术顺序，不改为一次性Schur求解，避免引入额外舍入差异。
- 重放每个零时恢复其原 `position`、物理模式、当时点击数、零数、kernel模式及相消信息。一个以前没有走过的新零分支若失败，会在消费下一模式uniform之前失败。
- 只有成功条件会插入。容量不足、数值失败均不通过重抽、改概率、回退到独立分布或丢掉样本处理。
- 若整条路径都命中，则这些中间零投影和后续条件此前已在相同路径上成功；可以复用成功结果。
- 原程序就不对最后一个输出执行 `advance`，因为后面没有条件需要该状态。新程序保持同样规则，不增加最后一次投影，也没有新增一次可隐藏的失败。

样本固定批次仍在首个失败处中止，保留失败记录。就原来的数值概率guard而言，失败符号仍属于同一扩展输出律。操作系统资源不足等进程错误仍是运行失败，不能用缓存内存上限将它们解释为目标分布证书。

完整Q枚举保留独立DFS路径，不查询或填充这棵树；抽样仍发生在枚举之前。`samples=0` 时即使请求缓存，也不分配树载荷。

## 4. 内存和实际运算计数

显式上限是1,048,576个节点，以及64MiB树载荷。当前构建中每个节点48字节，`N=65536`预留3,145,728字节，即3MiB；最大节点请求对应48MiB。字节上限不包含分配器元数据、Gaussian状态、样本数组或程序其他部分，不能当作整个进程峰值RSS。

预留、插入、查找以及状态重建均计入原生 `sampling` 时间。达到容量后不驱逐、不调整概率：缺失节点及其后续尾部直接走原算法。容量是资源参数，不是近似精度参数。

输出新增 `prefix_cache` 字段，记录请求容量、实际预留载荷、已用节点、命中/缺失、容量跳过、状态重建、重放零更新及完全无需构建状态的样本数。包装器检查这些计数与样本数、模式数相容。

原 `sampling_diagnostics` 现在表示**实际执行的运算**。缓存命中不会重复累计条件核请求、数值修正或小行列式次数；计数减少表示少做工作，不能据此声称物理近似误差或浮点精度改善。一个命中值此前至少被完整求值一次，因而整批所访问概率的最小值、最大值仍由实际求值记录覆盖。

## 5. 正确性门槛

冻结本机构建：

```text
.cache/click-prefix-native/click_sampler
SHA-256 a8d5a830e7167aab20f829bee74bc404736f2551ff42e6e48491caf301d0fc3f
```

构建仍为C++20、`-O3 -march=native -ffp-contract=off`、单线程，无fast-math。原小行列式核、Gaussian更新、选择器数学规则与支持保护未修改。

`results/iteration5_prefix_validation/validation.json` 记录13项unittest全部通过、24项详细检查、零失败、零跳过，并绑定二进制、C++源码、包装器、构建器和测试源码的SHA-256。源文件与二进制在运行期间未变化；对应源码快照、build记录和测试日志在同目录。

覆盖范围：

| 检查 | 已验证内容 |

| 容量1、3、17饱和 | 容量耗尽后正确走原核；同uniform和logQ不变 |

例如6模式全部64个输出各强制一次并重访，共128条轨迹、768个条件。缓存只实际求值63个不同前缀、命中705次；32次状态重建，96条样本无需创建Gaussian状态。全部输出与概率逐值相同。这个控制说明复用确实发生，不是仅新增了一个未触发的开关；它不是随机工作负载下的性能测量。

大模式的本地边界测试用独立热态，验证实现和路径复用；它们不能用作困难高亮度GBS的质量证据。TMSV有限轨迹控制也不升级为对任意浮点协方差支持正确性的证明。

## 6. 对预期收益的限制

该优化针对同一输入下的持续抽样。小模式或高概率共享前缀会重复访问许多条件，因而有机会避免大部分事件计算以及整条样本的Gaussian状态更新；原算法的小规模持续吞吐瓶颈由此得到一个直接可检验的实现改进。

它没有承诺所有模式数都加速。一般大模式样本的深层前缀大多不同，有界树可能很快填满；仍有最坏的稠密零更新立方成本。重建状态没有神奇地消除这些更新：遇到缺失尾部的样本仍需按原序执行先前所有零。缓存管理和预留也有成本，正式结果必须保留变慢案例。

完整二叉条件树最多有 `2^m-1` 个节点，但本实现不会事先构造全树，存储被显式上限约束；也不把小系统近乎遍历完毕后的吞吐外推到数百或数千模式。

最关键的科学范围没有改变：这轮缓存不修正第四轮高亮度后段点击偏低，也不改善给定Q与真实GBS目标P的TV。它提供保持Q的加速候选，质量仍由相同的D1/D2协议判定；尚未实现的遗漏点击logit补偿属于另一种会改变分布的研究问题。
