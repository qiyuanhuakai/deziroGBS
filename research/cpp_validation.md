# C++ 点击保留采样器：接口、验证协议与数值边界

日期：2026-11-04。本文件记录新 C++ 实现的正确性验证。编译语言带来的加速属于实现优化；固定 k 的采样模型仍是近似模型，没有由此变成一般 GBS 的精确采样器。

**当前正式版本为稳定 MI v3。**后续正式冷启动测试发现，首个 35 实例验证集遗漏了稀疏局部拓扑上的 pairwise 排序敏感性。原始记录完整保留；修正后新增 local2/local4 回归，37 个常规实例及全部 27 个正式输入的 Python/C++ 完整 Q 一致性门均已通过。下文保留早期结果的适用范围，并在最后说明原因、修正和新对照。

## 接口与随机数约定

`src/gbslab/cpp_click.py` 的 `run_cpp_click` 接受 `ThresholdModel` 或原始协方差、`selection`、`max_clicks`、`samples`、`seed`、可选模式顺序及显式均匀随机数矩阵。输入协方差使用 hbar=2、真空 I、xxpp 顺序，并检查对称、有限性和 Gaussian 不确定性关系；不会评价完整目标分布来拟合采样器。

显式 uniforms 的形状是 `(samples,modes)`，列按测量顺序排列。每一个模式都消耗一个随机数，包括条件概率恰为 0 或 1 的模式；点击规则是 `u < p_one`。返回样本的列始终按物理模式排列。完整分布的索引是 `sum(bit[i] * 2**i)`，物理模式 0 为最低位。C++ 与 NumPy 的相同整数种子不表示相同随机数流，因此跨语言逐轨迹检查使用同一份 uniforms。

普通抽样支持最多 256 模式；可选完整 Q 枚举限于 14 模式。枚举 Q 只用于验证，既不是目标 P 的计算，也不是实际抽样的前置步骤。`raw_samples=False` 可省去原始样本的 JSON 输出，`trace_conditionals=True` 和 `profile=True` 是显式诊断选项。

## 验证层次

验证程序固定使用以下测试，不根据结果挑选有利实例：

1. 真空、非同参数独立热态：完整分布有解析答案，热态同时检验协方差约定、模式顺序和采样位的物理索引。
2. Haar 8 模式和不同压缩、不同透射率的 Haar 10 模式：pairwise 与 click_influence 各自对 k=2、3、4，比较完整 C++ Q 与相同 Python 采样器 Q。
3. 3、4、5 模式的完全条件化实例，分别 k=2、3、4：只有这些一般态实例才把完整 Q 直接与完整物理目标 P 比较。截断模型只需检查前 k+1 个测量结果的精确物理边缘，因为此时尚不会丢弃任何历史点击。
4. 所有常规实例复用显式 uniforms，要求跨语言生成的样本位逐一相同。该检查与完整 Q 比较分别覆盖随机数调用约定及概率模型。
5. 独立无损 TMSV 对与弱热态作为独立数值压力测试：报告精确零支持、极小事件和相消保护所引起的明确失败，不把失败删除或当成已通过的概率计算。
6. 65 模式独立热态和 256 模式真空只抽样，检查超过 64 位的模式索引及大模式接口，没有指数规模分布或直方图。

完整 Q 比较的预设容差为 TV≤2e-9、单点最大误差≤2e-10；物理前缀最大误差≤2e-10；解析/完整目标 TV≤2e-9。逐位配对要求零差异。这些是双精度数值回归门限，不能解释成严格区间算术证明，也不提供截断模型本身的全局误差保证。

## 失败与档案

包装器检查程序退出状态、元数据、有限且归一化的概率、二元样本、直方图与样本一致性、报告的条件概率范围。非零退出或数值错误显式返回 `CppClickError`，保留 JSON 载荷、退出码及 stderr；不会自动重试，也不会用 Python 结果替代失败的 C++ 输出。近似模型与物理目标的不同、编译实现与 Python 模型的不同、浮点无法解析事件的失败是三个独立问题。

每次运行记录实际二进制 SHA256；只有临近的 build.json 所记 SHA256 与二进制一致时才绑定其构建缓存标识。整套集成验证前后再次检查二进制未改变。每个验证实例可归档协方差、模式顺序、uniforms、两种实现的样本和完整分布，以及目标参考（适用时）。记录数值失败、固定容差、版本和二进制身份，便于对同一个实现重放。

编译是显式步骤，普通单元测试不启动编译器。没有二进制时，依赖二进制的测试会明确 skip，接口输入/输出校验测试仍执行。

```bash
python experiments/build_click_sampler.py
PYTHONPATH=src python -m unittest discover -s tests -p test_cpp_click.py
python experiments/build_click_sampler.py --native --build-dir .cache/click-native
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 PYTHONPATH=src \
  python -m gbslab.cpp_click --validate --samples 64 \
  --executable .cache/click-native/click_sampler \
  --output results/cpp_validation/validation.json
PYTHONPATH=src python -m gbslab.cpp_click \
  --support-from results/cpp_validation/validation.json \
  --executable .cache/click-native/click_sampler \
  --output results/cpp_validation/support.json
```

验证会打开完整 Q 枚举和条件轨迹诊断，其时间不能作为采样速度的基准。性能实验须在正确性检查之后，以新建采样器和同一归档输入单独执行。

### 将采样支持检查与完整枚举失败分开

因为 C++ 的完整枚举发生在抽样之后，如果它失败，组合运行就不会返回原始样本。为避免这类后续失败掩盖先前的样本行为，`native_uncached_support.json` 用原先已归档的协方差、顺序和 uniforms，单独运行相同压力批次的抽样。此步骤是固定诊断的重放，不是给统计置信界补抽或替换失败样本。

4 个 TMSV 批次各 64 个样本全部完成，没有任何禁止的 A/B 配对模式。其中包含专门的边界输入：A 测量用接近 1 的随机数、B 用 0，以及反向组合，主动检查条件化后本应禁止的分支。k=2 的两批与 Python 逐位一致；k=4 的 Python 抽样触发数值保护，C++ 成功生成了通过支持检查的样本。2 个弱热态批次在两种实现中都明确失败。

这说明受检查轨迹的抽样没有出现支持违规，同时保留了无损精确支持的数值局限：完整 Q 枚举尚未通过，不能宣称所有历史或所有极小事件已经被严格处理。所有 35 个主验证实例的文件、协方差及 uniforms 哈希均已核对；验证源文件与参考实现已保留快照。

### 计时对齐与每步缓存版本

`results/cpp_validation/native_cached.json` 及 `native_cached_support.json` 对应二进制 SHA256 `021e7d14ee43f9659809a0c7fe2add871dc9f0a551d4cbf389fcb8321adf4bd5`。该版本总是实际写出压缩位样本，采样计时包含 RNG 初始化和样本缓冲区分配；直方图和每模式点击计数归入单独的聚合阶段。每个条件步骤内部复用重复的真空概率，避免重复计算相同的小行列式。

再次执行完全相同的 35 个主实例和 6 个抽样支持诊断后，结果相同：29 个常规实例通过、6 个主压力实例明确保护失败；单独抽样的 4 个 TMSV 批次没有支持违规，2 个弱热态批次保护失败。与首个版本相比，所有已成功得到的完整 Q 数组和样本数组都逐位相同，输入及 uniforms 的哈希也一致。上表最大误差没有变化，15 项普通单元测试全部通过。

这次回归只确认缓存与计时调整没有改变受检实例的数值输出。实际加速幅度由根实验的匹配输入、冷启动和批量采样基准给出；正确性验证的枚举/轨迹时间仍不作为性能证据。

## 正式局部拓扑测试发现的覆盖缺口

原生二进制 `021e7d14...` 在 `results/cpp_cold/` 的 27 个正式实例中，有 13 个 pairwise 完整分布与历史 Python 对照的 TV 超过既定 2e-8 门限；这些情况都来自 local2 或 local4。全部 27 个 click_influence 对照的差异仍小于 9.5e-14。诊断数据保存在 `results/cpp_validation/local_tie_diagnosis.json`，原冷启动结果没有被覆盖。

最大 pairwise 分歧来自 `a71ab6f032848177`：10 模式、local2、r=0.8、eta=0.5、uniform、seed=5101，跨语言 TV 为 0.004377654238。在测量模式 9、历史位串 mask=466 时，点击集合为 {1,4,6,7,8}，零集合为 {0,2,3,5}。模式 9 与模式 1、4、6 的协方差交叉块都精确为零，其真实未条件化互信息均为零；历史 Python 却为模式 6 算出约 6.99e-18 的正分数，因而保留了不同集合。

同一 Python 概率内核对 {8,7,6,1} 给出点击概率约 0.4193112741，对 {8,7,1,4} 给出约 0.5630043771，分别重现了历史 Python 和 C++ 完整分布的转移。差异已经被隔离到选取的历史点击，不需要改变条件概率内核解释。观察其他模式以后，原先边缘独立的候选模式可以产生不同的条件预测作用，因此极小排序误差能够变成明显的分布差异。

原验证集没有覆盖这个组合：Haar 实例缺少稀疏结构零，独立热态/真空的候选即使互信息打成平手也具有相同条件作用，而完全条件化的小实例不会执行截断选择。新增回归使用固定 local2/local4 光学实例，并加入强制经过历史 466 的同一份 uniforms，避免只依赖小随机批次偶然碰到有关历史。

## 稳定 MI v3：限定范围与代数

修改仅作用于点击保留采样器的 Gaussian pairwise 分数。历史 Bayesian-network 对照及 click_influence 的评分规则不变；没有协方差 V 的解析 oracle 继续使用原先的联合边缘分数路径。所有条件概率与完整 Q 门限保持不变。

若原始 Gaussian 协方差的两模式交叉块 C 精确为零，直接设 MI=0，沿用物理模式 ID 的平手排序。对于非零 C，使用显式 long-double 标量 2×2 Cholesky 和三角求解。令 A=V_ii+I、B=V_jj+I，

\[
T=L_A^{-1} C L_B^{-T},\qquad
s=\|T\|_F^2-\det(T)^2,
\]

并由原始协方差的单模 Cholesky 因子得到无点击概率 a、b。两模式无点击相关量采用

\[
\delta=ab\,\operatorname{expm1}\!\left[-\tfrac12\operatorname{log1p}(-s)\right].
\]

这避免直接相减两个几乎相等的真空概率。对独立 Bernoulli 乘积分布的四个单元 r，联合概率是 r+delta、r−delta、r−delta、r+delta。互信息写为

\[
\operatorname{MI}=\sum_j r_j h(x_j),\qquad
h(x)=(1+x)\log(1+x)-x,
\]

其中未发生概率修正时直接用 x=±delta/r。对 |x|≤1e-3 使用 h 的二至八阶级数，x=−1 时取 h(−1)=1。单元负概率、归一化和累计修正仍受已有概率保护限制；需要修正的边界情况重新计算修正后的边缘及乘积分布。没有把小正 MI 强制归零的 epsilon floor。

独立解析测试确认，n1=0.7、n2=1.1、C=1e-4 I 的物理双模热态相关实例得到约 3.18436517e-19 的正 MI，与 80 位 Decimal 的直接联合概率计算一致。另有 TMSV 的 MI=log2 边界测试、没有 V 的解析配对 oracle 测试，以及精确零和非零弱相关 local4 分数回归。
